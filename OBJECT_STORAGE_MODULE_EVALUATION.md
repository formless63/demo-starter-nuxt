# Object Storage module evaluation

Capability #4 is the private optional `@repo/nuxt-storage`, using the existing Nuxt package/catalog/fixture lifecycle. No publication, database records, File UI or second capability is included.

## Sources and version decisions

- AWS SDK v3 client S3 and request presigner **3.1143.0**, current stable registry release when implemented, pinned together. [Official presigner documentation](https://github.com/aws/aws-sdk-js-v3/tree/main/packages/s3-request-presigner) explicitly supports `signableHeaders` and `unhoistableHeaders`; both are essential to enforcing exact Content-Type and metadata. [Credential providers](https://docs.aws.amazon.com/sdk-for-javascript/v3/developer-guide/migrate-credential-providers.html) establish the Node default-chain contract. No provider SDK or unnecessary `lib-storage` dependency.
- RustFS **1.0.0**, upstream non-prerelease release and official `rustfs/rustfs:1.0.0`. [Release](https://github.com/rustfs/rustfs/releases/tag/1.0.0), [official Docker/named-volume/non-root documentation](https://docs.rustfs.com/en/installation/container/docker), [CORS](https://docs.rustfs.com/en/administration/cors), [S3 compatibility source](https://github.com/rustfs/rustfs). Preferred self-hosted target, not blanket AWS feature equivalence.
- Garage **2.4.1**, upstream stable release, `dxflrs/garage:v2.4.1`. [Releases](https://git.deuxfleurs.fr/Deuxfleurs/garage/releases), [quick start](https://garagehq.deuxfleurs.fr/documentation/quick-start/) documents the explicit single-node/default-bucket bootstrap added in 2.3; [S3 compatibility](https://garagehq.deuxfleurs.fr/documentation/reference-manual/s3-compatibility/) is guidance, not a substitute for testing. Single-node dev layout, SQLite and persistent named volume; application code remains normal S3.
- Third-party [Noooste Garage UI **v0.13.0**](https://github.com/Noooste/garage-ui/tree/v0.13.0), exact image `noooste/garage-ui:v0.13.0`, is optional localhost development/operator tooling, **not official Garage software and not required for S3**. The tagged README and [configuration source](https://github.com/Noooste/garage-ui/blob/v0.13.0/backend/internal/config/config.go) document `GARAGE_UI_GARAGE_TOML`, endpoint overrides, port 8080 and token authentication. We mount existing `garage.toml` read-only, override S3/admin endpoints with Compose service addresses and explicitly set `GARAGE_UI_AUTH_TOKEN_ENABLED=true`. The UI reads the privileged admin token/region from TOML; no separate S3 credentials or obsolete password/bcrypt configuration is needed. [Tagged routes](https://github.com/Noooste/garage-ui/blob/v0.13.0/backend/internal/routes/routes.go) establish public `/health` and `/auth/config`, token exchange `/auth/login-token`, and authenticated `/api/v1/cluster/status`. Real tests reject empty/wrong/S3 tokens, check non-secret public auth metadata, exchange the local admin token for a distinct signed session token, and read cluster status through the Garage 2.4.1 admin API. Administrative secrets stay outside browser application code and normal S3 clients; the operator UI is a separate privileged trust boundary. Known dev tokens are local-only; reassess security before upgrades/nonlocal exposure.

## API/configuration boundaries

`/server` creates a lazy Storage instance: bucket/region/optional endpoint, paired static credentials/session token or unchanged AWS default chain, custom-endpoint path-style default (AWS default false), bounded 600-second-default TTL, safe key prefix. Explicit configuration and isolated `env` permit standalone usage without Nitro globals. Region resolves `STORAGE_REGION` → `AWS_REGION` → `AWS_DEFAULT_REGION` → safe configuration error on use, with no implicit region. Explicit options take precedence. Installing/building/booting with no bucket/region/backend is valid; first use validates. Local helpers explicitly supply RustFS `us-east-1` and Garage `garage`, never provider fallbacks inside the package. No fake Nuxt dependency on Drizzle/auth/Jobs/Observability; only `getStorage` is auto-imported, not Nitro's existing `useStorage` name. Supported Kit imports/plugin close hook avoid runtime loaders/router additions.

### Shared cross-framework baseline

Nuxt and TanStack share AWS SDK client/presigner 3.1143.0, preferred RustFS 1.0.0, alternate tested Garage 2.4.1 and optional third-party Noooste Garage UI v0.13.0. Browser primitives are presigned PUT + GET, default TTL 600 seconds with 30–3600 bounds. A custom endpoint defaults to path-style; no custom endpoint retains normal AWS behavior. Region uses the explicit resolution above. Credentials are a complete explicit pair (optional session token) or the SDK default provider chain. Objects stay private by default and application startup never provisions buckets. Normal Nuxt packaging/lifecycle is retained; framework implementation details need not mirror TanStack.

Instance API covers bucket HEAD check, PUT, streaming GET, HEAD, DELETE, paginated bounded ListObjectsV2, signed GET/PUT, multipart create/part signing/complete/abort, random namespaced keys, HEAD policy verification and an explicit SDK escape hatch. Returned metadata normalizes key/size/opaque ETag/type/cache/modified/user metadata. No public ACL/bucket policy/public URL. Authorization, original filenames, acceptance records and multipart state belong to applications. Keys are validated, never raw filenames; prefix is naming, not tenant isolation.

Errors are safe bounded codes, not raw SDK error stacks/credentials/signed URLs. SDK automatic optional checksum request/response behavior is explicitly `WHEN_REQUIRED` for portable self-hosted semantics. This does not prove content integrity: consumers needing cryptographic integrity/encryption/versioning must choose and test stronger mechanisms. No real AWS account was used; AWS endpoint resolution, static/default-chain configuration and signing are locally tested, while IAM/workload environments and wider AWS features remain deployment responsibilities.

## Direct uploads, multipart and streaming

GET/PUT are the required common browser interface; presigned POST is deliberately excluded because RustFS POST form checksum compatibility is incomplete/planned. Merely setting SDK `ContentType` is insufficient: force `content-type` into `signableHeaders` and metadata into `unhoistableHeaders`, returning all required headers. Wrong Content-Type must fail, not silently create an object. Cache control is also signed when specified. Short-lived URLs are bearer grants and may expire with temporary credentials before the requested TTL; never log their query strings.

Direct PUT cannot universally impose hard pre-ingest byte limits. HEAD verifies max bytes/exact type/expected metadata after upload and optionally deletes the explicitly selected failing object; client checks are UX. Proxy uploads or deliberately supported stronger policy are needed for pre-ingest hard limits. HEAD does not prove malware/type content and replacement races require consumer policy, not invented upload-intent database state.

GET preserves the SDK streaming body; consumption or destroy/cancel is caller-owned. Smoke buffers only known-small/generated test objects. Multipart validates opaque IDs/ETags, 1–10000 part numbers and ascending unique completion shape. Real tests upload a 5 MiB first part and small final part, complete/read and abort/reject reuse. No worker, UI or durable state is hidden in these primitives.

## Infrastructure and CORS

`compose.storage.yaml` is an additive native Compose include of the exact fixture-owned provider definition. Sharing local/fixture assets prevents copied bootstrap graphs. Root normal Compose keeps postgres/migrate/app/worker; only optional app environment pass-through is added. Storage is not critical root health readiness. The default reference image builds/boots with no storage provider.

RustFS named volume needs no manual host UID setup; custom non-default dev credentials, localhost API/console and `RUSTFS_CORS_ALLOWED_ORIGINS` are explicit. Garage's `--single-node --default-bucket` deterministically establishes node/layout/key/bucket using dedicated dev values; persistent identity stays in its named volume. Bucket CORS is set explicitly on both providers via standard S3, with trusted local origin, exact needed headers and exposed ETag. Allowed and untrusted preflight tests verify actual responses. Production origins must be explicit; CORS is not authorization. Garage admin/RPC are not host-published; Noooste UI is localhost-bound with operator token login. Committed dev secrets are not production configuration.

Provider bootstrap is explicit development/test code, not public runtime API; normal app startup never creates buckets/containers. `storage:check` is read-only; `/testing` provides reusable unique-prefix smoke/cleanup. Thin root adapters are sufficient, so no bin is invented merely to match Jobs; no consumer package scripts are rewritten. Development `down` retains volumes; temporary test project teardown deletes only its own generated volumes.

## Optional telemetry

An optional generic `runOperation` runner works independently of OTel. Root wrapper records `storage.<bounded operation>` spans and `app.storage.operation.duration`/`bytes` with operation/outcome only. Known PUT bytes are measurements, not dimensions; GET duration ends at stream acquisition, consumer-owned transfer completion/errors remain separate. No bucket/key/filename/upload ID/user ID/signed URL logs or dimensions. [Current S3 OTel conventions](https://opentelemetry.io/docs/specs/semconv/object-stores/s3/) remain Development and include object identity; the bounded application instruments fit this safety contract better. Jobs is documented only as a future optional consumer; neither integration is a dependency.

## Lifecycle and verification

The catalog owns package/fixture/dependencies/runtime/removal metadata. Generic tarball install proves AWS dependencies arrive; a clean Nuxt fixture builds without storage settings, then runs the same actual provider contract and production Node auto-import check against RustFS/Garage, before clean removal verifies AWS dependencies disappear and Nuxt still typechecks/builds. The optional UI gets authenticated reachability/configuration checks, not storage parity credit. No handwritten Storage CI job is needed.

Local verification passed on the actual artifacts: RustFS 1.0.0 and Garage 2.4.1 both passed bucket HEAD, private/anonymous rejection, PUT/streaming GET/HEAD/delete, metadata/cache round trip, bounded prefix pagination, presigned GET/PUT, exact Content-Type and mismatched-type 403, HEAD size/type/metadata policy with failure cleanup, real two-part multipart completion/read and abort/reuse rejection. Smoke honors configured key prefix and proves its objects are removed. Both passed allowed/untrusted CORS preflights. Noooste Garage UI v0.13.0 separately passed health/frontend reachability, token auth enablement, wrong/empty/S3-token and unauthenticated-admin rejection, a signed operator session and successful Garage 2.4.1 admin communication. The root Compose include also served the exact UI version on localhost with token auth enabled. No S3 operation was skipped for parity.

All four real packed install/runtime/removal lifecycles passed (existing API fixture uses an isolated empty database). The broader temporary reference removal passed catalog/typecheck/build without external-resource changes. Frozen installation, catalog validation, clean app/pg-boss migration/doctor/smoke, lint, strict typecheck, 38 tests in 12 files, production build and Playwright all passed. The Storage fixture additionally passed production boot with all Storage/AWS variables absent; region unit tests cover all sources/precedence and safe lazy missing-region errors. Rebuilding packages and running the reference server must be sequential because module build cleans `dist`; local fixture temporaries under root `node_modules` also cannot coexist with a root Nitro build's dependency scan. Reference-copy source builds use `/tmp`, not a `node_modules` path.

The shared non-root production image passed the explicit container migration gate, app/worker health and real worker execution with no storage provider/configuration. Local development RustFS/Garage bootstrap and stop were exercised; stop retains volumes. The unchanged CI matrix now discovers Object Storage from `done` metadata and runs its capability-owned Docker hook alongside existing packages; hosted CI must remain green before handoff. No provider operations are skipped and no real AWS/production credentials or systems were used.

## Publication and lessons

Compared with Jobs/API/Observability, Storage owns no database migration, durable worker or auth boundary. Its risky contracts are signed-header enforcement, stream lifecycle, credential-chain portability and real provider parity. One package-owned smoke contract with capability-local provider bootstrap is simpler than custom package-matrix orchestration. Before npm publication choose a scope, audit tarball/API/peer/license support, separate fixture/dev assets as appropriate, review stable provider/UI versions and document any provider-specific supported-feature limits. Nothing is published now.

Ops composition uses a narrow optional server construction retry override passed to public S3Client `maxAttempts`; ordinary default remains 3. [Official AWS retry configuration](https://docs.aws.amazon.com/sdkref/latest/guide/feature-retry-behavior.html) was checked 2026-10-01: attempts include the first request and 1 disables retry. No SDK middleware internals are changed.
