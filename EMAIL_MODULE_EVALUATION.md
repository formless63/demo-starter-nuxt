# Email module evaluation

## Decision and current official sources

Use private publish-shaped `@repo/nuxt-email`, Nodemailer **10.0.13** (current stable registry release verified 2026-09-30) and **axllent/mailpit:v1.31.3** (current stable upstream release). SMTP is the portable primitive; vendor HTTP SDKs would couple the common contract to a provider. Nuxt 4.5.2 is the peer, @nuxt/kit4.5.2 and Nodemailer are runtime dependencies; module-builder1.0.3 and @types/nodemailer8.0.2 are development-only. No DB/Better Auth/Jobs/Observability dependency. Existing generic catalog-driven tooling handles preparation, packed installation, runtime fixtures and removal; no custom loader or Email CI orchestration.

## Transport and security contract

Configuration is lazy: install/build/boot can omit every SMTP setting; get/create/send/verify validates on use. Root enabled magic links validate structure when constructing auth. Explicit `SMTP_SECURITY` is independent of port: tls=secure:true; starttls=secure:false/requireTLS:true; opportunistic=secure:false/requireTLS:false. There is no certificate-validation bypass. User/password must appear together or neither; the latter supports the unauthenticated local sink. Server overrides accept only reviewed config fields, never Nuxt public runtime config.

Connection/greeting deadlines are 5 seconds, socket 10 seconds. No pooled transporter, startup connection, auto send, route, table or implicit local service. Manual instances close explicitly; Nitro closes the lazy singleton.

Config owns From and default Reply-To. Per-message To/Cc/Bcc/Reply-To are structured mailbox/name objects, not arbitrary RFC strings. Conservative mailbox shape, bounded labels and CRLF/control rejection deliberately avoid full RFC implementation. Subject ≤998 characters, combined text+HTML ≤1MiB UTF-8; recipients default50/max100, with transport maxRecipients also set. Nodemailer10's own bounds complement application validation. Message-ID is generated by Nodemailer and returned to the caller, never telemetry.

Transport uses `disableFileAccess:true`, `disableUrlAccess:true`, logger/debug:false. Input is validated then projected into an allowlisted message; extra headers/raw/envelope/DKIM/attachments/path/href/content-source objects are rejected. No fetching, HTML-source loading or data-URL attachment conversion. The tiny text+HTML magic-link renderer escapes HTML and allows only canonical HTTP(S) origin. Product templates belong to consumers.

## Delivery and error model

One sendMail per operation, **no retry**. Accepted/rejected/partial results expose only counts and Message-ID; partial acceptance returns a deliberate outcome rather than an automatic-retry exception. Explicit SMTP4xx rejection maps temporary/retryable; SMTP5xx permanent/nonretryable, 535/EAUTH authentication. Connection refusal/DNS errors are retryable; unspecified connection loss, timeout/reset/socket/unknown states are conservatively nonretryable because acceptance may already have occurred. TLS errors remain bounded. Errors retain cause server-side, but JSON and Node inspection expose only code/retryable/safe message. Callers must not explicitly log `.cause`.

SMTP network loss can follow acceptance, so even a retryable classification is advisory: applications need idempotency and duplicate-delivery policy. Jobs can compose Email in domain handlers but arbitrary recipients/bodies are not persisted to pg-boss. Generic durable queues are deferred until privacy, retention and delivery semantics are defined, potentially with Notifications.

## Mailpit and root integration

Mailpit is a localhost-only disposable sink with bounded100 messages, no persistent volume, relay/forward/release config or remote CSS/fonts. `MP_ALLOWED_HOSTS` is explicit (current Host-header/DNS-rebinding hardening). Normal production/PostgreSQL Compose is unchanged; app-in-Compose uses service hostname on an intentionally shared network. Fixture enables Chaos only in its disposable container; API is assertion/cleanup-only, all delivery uses SMTP.

Root Better Auth retains `storeToken:'hashed'`, validates generated URL against canonical app origin and awaits SMTP text+HTML delivery. Console magic links and production-only prohibition are removed. Disabled magic links require no SMTP. Root telemetry is optional application composition with bounded operation/outcome/security and numeric duration/count; no identities/content/Message-ID/SMTP response. `/api/health` continues DB readiness.

Purelymail documentation example: smtp.purelymail.com465/tls or587/starttls, full mailbox username and account/app password. SPF/DKIM/DMARC and sender-domain reputation stay provider/operator concerns. No test sends to that provider.

## Verification and removal

Local verification passed: frozen installation; agents checker and 96 harness tests; capability status/check; all five packed install/runtime/removal fixtures; lint/typecheck; 48 unit/integration tests with migrated PostgreSQL; production build; Playwright; production image/migrations/application health/worker smoke. The actual built Nitro auth endpoint also delivered and redeemed a canonical magic link, with session confirmation and private logs. A temporary root copy passed harness/catalog/typecheck/build after Email removal and disabling magic links. The external tarball fixture covers backendless production boot, SMTP verify-without-send, plaintext/HTML/multipart/Unicode, From/Reply-To/To/Cc/Bcc, hidden Bcc headers on the SMTP wire (Mailpit synthesizes an envelope-derived Bcc header in storage), Message-ID, limits/content-source rejection, partial acceptance, deterministic sender-stage451 temporary/retryable and550 permanent/nonretryable, each with exactly one counted SMTP connection and no stored delivery, bad authentication and refused connection. Root tests exercise the actual Better Auth HTTP handler with root plugin composition and migrated root schema, capturing and redeeming the link internally, checking hashed token storage/session and absence of secrets in logs. No token/link is printed.

Package removal proves Nodemailer disappears and base Nuxt rebuilds. Root removal requires disabling magic links or an intentional alternative sender, removing dependency/module/wrappers/local helpers/env/reference enablement, then normal verification. No DB migration, SMTP account/DNS change or remote credential revocation. Private scope and package metadata need publication review before release, as with earlier capabilities.

Lessons: Email follows Storage's lazy standalone primitive and app-owned optional telemetry; unlike Storage, SMTP acceptance is not reliably idempotent and partial recipient acceptance is normal. Better Auth integration belongs to the root, not the module. A disposable actual protocol sink provides stronger evidence than mocked sendMail while leaving expensive verification out of per-turn hooks.
