# Webhooks module evaluation (September 2026)

Research checked the current [Standard Webhooks spec](https://github.com/standard-webhooks/standard-webhooks/blob/main/spec/standard-webhooks.md), its [maintained JS implementation](https://github.com/standard-webhooks/standard-webhooks/tree/main/libraries/javascript), npm `standardwebhooks` **1.1.1**, [Node 24 fetch/AbortSignal](https://nodejs.org/docs/latest-v24.x/api/globals.html) and [crypto](https://nodejs.org/docs/latest-v24.x/api/crypto.html), plus the installed pg-boss **12.35.0** declarations/manager/SQL through the Jobs package contract. Nuxt 4.5.2's actual module dependency types support the required versioned `moduleDependencies` relationship.

The spec uses `webhook-id`, integer attempt `webhook-timestamp`, `webhook-signature` with space-delimited `v1,<base64>` signatures and HMAC-SHA256 over `id.timestamp.payload`. IDs/timestamps cannot contain dots. Event timestamps differ from refreshed delivery attempt timestamps. Rotation and constant-time comparisons are required. The spec also supports asymmetric ed25519; this first capability intentionally implements the requested symmetric scheme only. Use unique random 24–64-byte secrets per endpoint. The stable envelope follows the requested `{ id, type, createdAt, data }`; Standard Webhooks does not require one business envelope field naming convention.

The maintained JS package converts Buffer payloads to strings for signing. Native Node `createHmac` signs exact bytes with no UTF-8 replacement and `timingSafeEqual` compares equal-size decoded digests. This smaller server-only implementation rejects malformed timestamp/secret encodings, bounds secret/signature counts and is tested against the maintained JS reference in both directions for valid JSON/UTF-8, plus exact binary-byte vectors. The reference package is a root **test-only dev dependency**, not required by consumers.

Native fetch is stable in Node 24. `redirect: 'manual'` avoids forwarding signed requests to another destination; bodies are never read, so remote response read size is zero. A bounded abort controller wraps target resolution, application policy and fetch; Jobs signals compose with it. A request timeout does not guarantee the remote endpoint did not accept it. Read duration/bytes are independently bounded inbound, including a lying/absent Content-Length.

Jobs is a true dependency: catalog `requires`, versioned Nuxt module dependency and a Jobs peer express it consistently. The fixture explicitly installs/enables both. `createWebhookJobs` returns a public Jobs definition and payload preparation helper, composed into the application's existing registry. No new worker or Jobs internals are introduced. Secrets are resolved each attempt, never queued. pg-boss retries all thrown failures; retryable delivery errors are thrown sanitized, whereas permanent 4xx/redirect/configuration errors return a terminal rejected outcome. Per-send options enforce bounded count, delay, jitter/backoff cap, expiry and retention without rewriting queue records or generic history. Failed state on exhaustion and completed-with-rejected business outcome are both tested against real PostgreSQL.

Generic lifecycle tooling previously packed only the selected capability, so a true package dependency would leave `workspace:*` unresolved in its external fixture. It now computes a catalog-driven hard dependency closure, packs each package and substitutes local tarballs. Removal keeps those hard-dependency packages and verifies their continued installation. No Webhooks-specific lifecycle or CI branch is added. The packed inbound boot/enqueue test also exposed implicit Nitro globals in the existing Jobs plugin/client that were transformed in workspace source but not installed node_modules. Both now import their helpers explicitly from `#imports`, matching the established Observability package pattern; this is a prerequisite correction rather than a Jobs capability expansion.

No generic replay table is invented: Jobs singleton keys/windows are scheduling semantics, not durable ID acceptance across retention/replay/manual redelivery. Applications provide `runOnce` with atomic durable claim and transactional work/enqueue. The package clearly distinguishes timestamp freshness from replay storage and outbound at-least-once delivery. Target URL literal checks cannot prevent DNS rebinding; trusted target registries, application DNS/egress policy or allowlists must handle that. Local HTTP is an explicit fixture-only opt-in. Optional telemetry/Audit/API patterns import no capability into Webhooks.

The root opts in with a registered demonstration event and an unconfigured safe target resolver; build/boot/health and the production worker require no webhook endpoint or secret. The smoke harness configures a temporary local receiver deliberately. Removal retains Jobs and external resources. Endpoint CRUD, UI, subscriptions, business integrations, Email, Audit Log, Cache and Notifications remain outside this capability.

Shared defaults are aligned with the integrated contract: 64 KiB queued body (1 MiB direct maximum), lowercase event grammar and JSON-safe schema output, 10-second delivery/read timeout (100 ms–30 seconds), timestamp tolerance 300 seconds (900 maximum), five retries after the first attempt, 30-second initial delay and exponential backoff capped at 900 seconds, active expiry 60 seconds and completed retention one day. Completed retention uses pg-boss `deleteAfterSeconds`, distinct from existing seven-day queued `retentionSeconds`. Deliberate duplicate enqueues create separate work; scheduler retention is not application idempotency.

Verification passes all eight packed capability lifecycles, maintained-reference interoperability and exact-byte unit tests, actual PostgreSQL/Jobs worker delivery/retry/permanent/exhaustion and Nitro inbound checks, retained Jobs removal, and the production non-root migration/app/worker path with no remote targets. Root verification includes 98 agent tests, 67 Vitest tests and three Playwright tests in development and production.
