# Ops / Admin

Status: done. Private `@repo/nuxt-ops-admin`, opt-in for clean consumers; explicitly enabled in the reference application. Requires baseline Authentication and Node runtime, no capability dependency, service, migration, worker or persistence. Optional application-owned integrations: Observability, Jobs, Audit Log, Object Storage, Cache / Coordination, Webhooks.

Enable the package in `modules` and configure `opsAdmin.application` to a server module exporting `opsApplication`. That application supplies the baseline Better Auth `resolveSession(event)`, a static `createOpsService(registry)` and optional guard. Missing configuration defaults to no authenticated session. Never resolve API keys as human sessions. Server GET `/api/ops/summary` authorizes every request; the native `/admin/ops` page uses cookie-forwarded server data fetching, accessible denial and manual refresh only.

`OPS_ADMIN_USER_IDS` is privileged platform-wide visibility: a server-only comma-separated list of opaque baseline user IDs, default empty/deny. Trim entries, ignore blanks, deduplicate; at most 100 distinct validated IDs after deduplication, each 1–128 UTF-16 code units without control characters. Malformed configuration fails Ops closed with 503 without blocking startup. Never use email/roles/public config/localhost promotion. A guard defaults to narrowing the allowlist; explicit `guardPolicy:'replace'` requires a guard and intentionally replaces membership, still requiring a valid human session. No implicit OR. Organization selection/ownership and API-key grants do not authorize Ops.

## Safe adapter contract

Static maximum 16 adapters, unique lowercase machine `id` (1–64), plain title (1–80), pure `isConfigured()`, read-only `inspect({signal})`. Register at most eight unique machine `countNames`; returned counts must use those names and be nonnegative safe integers. Missing configuration never inspects. Invalid registry fails Ops locally at request time, not unrelated startup. Outputs are copied to a closed projection, never arbitrary provider details.

Summary `{checkedAt,adapters:[{id,title,status,checkedAt,durationMs?,counts?,code?}]}` remains in registry order, with UTC ISO millisecond timestamps. Optional adapter `checkedAt` denotes provider sample time; otherwise it denotes inspection time. Status: ok/degraded/unavailable/not-configured/timeout. Safe codes: unavailable/timeout/not-configured/invalid-result/sample-unknown/bounded-window/capability-present. Maximum encoded response 64KiB. No arbitrary targets/filter/sort/diagnostic URLs. Errors expose only `{code,message,retryable}` from the closed map; unauthenticated 401, forbidden 403, configuration/unavailable 503, limit 413. Partial adapter failures return 200.

Per-adapter deadline 3000ms, summary deadline 5000ms, process/service inspection concurrency three. Signals reach supported I/O; disconnect aborts pending card waits. For older non-cancellable APIs, Ops stops awaiting at the deadline but retains at most one pending invocation per adapter/service and reuses it until settlement; actual pending work consumes a concurrency slot. It does not claim to cancel underlying work. Late rejections are safely handled; no retries. Registries must be singleton application-owned instances, not recreated per request. These read-only shared pending results must never depend on per-user context; no retained settled summaries or sessions.

Reference Storage owns a separate lazy client with `maxAttempts:1` (ordinary Storage remains three attempts), using existing bucket HEAD and Cache uses existing connection/PING only. Their older APIs do not support caller AbortSignal; bounded pending reuse applies. Storage cancellation integration must be coordinated separately. Jobs/Webhooks use a lazy reader-role client and bounded registered-name getQueues metadata only, sharing pending work. They omit counts with explicit sample-unknown because getQueues lacks a sample timestamp and defaults may not have been sampled; getQueueStats can refresh/write stale caches and is not used; Audit shows capability-present without an unbounded scan. Observability shows local enabled state, never collector configuration. No optional provider participates in startup/readiness. No raw values, names, URLs, keys, sessions, credentials, payloads or errors reach HTML/JS/logs. Ops emits no logs or telemetry by default.

## Removal

Remove the root dependency/module and `opsAdmin` option, `server/ops`, `server/plugins/ops-admin-jobs.ts` and `server/plugins/ops-admin-storage.ts`, any navigation link, and the allowlist environment configuration. Remove each optional adapter/import independently when its capability is removed. Do not clean provider resources or database data. Package removal has no migration/worker/session cleanup. The generic `bun run packages:test ops-admin` packs real tarballs and verifies consumer install/runtime/removal/rebuild; no registry publication.
