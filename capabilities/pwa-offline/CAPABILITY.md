## Scope and threat model

This is an installability/lifecycle primitive and an inert public offline notice, **not** a local-first app or an offline account session. No background sync, mutation queue, push, user-data storage, account snapshots or persistence are implemented. Only three fixed capability-owned files are precached: the inert HTML notice and two content-fingerprinted PNG icons. All app JS/CSS, SSR documents, navigation responses, APIs, auth/callbacks, uploads, dynamic content, errors and third-party URLs are excluded. Files merely placed in `public` are never discovered. Native `@vite-pwa/nuxt` 1.1.1 with `vite-plugin-pwa` 1.3.0 `injectManifest` uses Workbox build 7.4.1 with empty globs, automatic registration disabled, icon auto-inclusion disabled, and a transform returning the fixed allowlist. The plugin's automatic manifest entry is explicitly cleared; the web manifest is public but not cached by this worker.

SHA-256 integrity is computed from these three build-reviewed files and passed to each Fetch request with `credentials: omit`, `redirect: error`, `cache: no-store`. SRI rejects changed bytes before a cache write. New install fetches share a 15-second abort deadline. Each response must additionally be basic, exact same-origin URL, status 200, not redirected, public and not private/no-store/no-cache, with only absent/Accept-Encoding Vary and a fail-closed unquoted Cache-Control directive grammar, and exact expected HTML/PNG MIME. PNG responses must be immutable. Content-fingerprinted filenames must be updated when icon bytes change. A failed install removes only a newly created versioned partial cache. An already-existing complete same-version cache must pass exact URL-count, response-header and SHA-256 checks, and is reused without any writes. Existing incomplete or invalid caches fail closed without deletion. This protects an active worker when emitted bytes change without a content-version change. Worker/policy/config/assets/native-module/toolchain identity contribute to cache versioning; activation cleans only the prefix containing this exact origin and scope.

This defends against accidental personalized responses and storage of returned private bytes; it is not an XSS defense. Same-origin compromised scripts, compromised build sources or an administrator changing the reviewed allowlist are trusted-origin compromise. Other application code, HTTP cache and preexisting workers are outside this module's storage guarantee. Cookies, Set-Cookie side effects or third-party browser storage policy are not claimed to be erased by logout. The worker itself never reads or stores a session. Cache eviction, private browsing, platform support, device installation and delayed update checks remain browser-controlled.

## Installation and native build

Install private `@repo/nuxt-pwa-offline` and explicitly include it in `nuxt.config.ts` modules. Package presence alone does not enable it. The native module owns @vite-pwa/nuxt, disables its automatic client registration, copies only three reviewed assets through Nitro, and emits a live manifest link in SSR. Render `PwaPanel` on an application-owned public route. The default `pwaOffline.publicOfflinePaths` is empty; the reference app explicitly selects `['pwa-test']`. The component's buttons remain disabled until mounted; registration requires the explicit Enable button.

`pwaOffline.base` defaults to and must exactly equal Nuxt `app.baseURL`. Both are slash-terminated simple local paths. Worker URL is `<base>pwa-offline-sw.js`; scope and manifest ID equal base. Cache ownership includes the complete origin/scope URL. The module assigns exact public asset headers with explicit UTF-8 HTML, immutable fingerprinted PNGs, and a revalidated JavaScript worker. HTTPS or loopback is required.

Nuxt generates the worker at `nitro:build:public-assets`. Its native module appends payload/app-manifest globs; the final native hook clears both globs and additional manifest entries. The transform refuses unexpected precache input and returns exactly the reviewed three entries. Worker sources are recreated before Vite resolution and native generation because Nuxt cleans generated sources. Builds/tests must verify live-worker identity and actual Nitro HTTP status/MIME/bytes, SSR manifest and exact asset hashes. Existing tombstones are never accepted as evidence for a live build.

No secrets, environment variables, provider connections, migrations, runtime service or infrastructure are added. `@repo/*` remains a private workspace scope, not public npm publication.

## Lifecycle, install UX and updates

Registration is explicit, idempotent while pending and refuses any overlapping registration with another script URL or scope; it never replaces an unrelated worker. Listeners are installed once per live subscription and detached after the last subscriber. All SSR action buttons are disabled until hydration. `beforeinstallprompt` is retained only when browser-trusted, and `prompt()` is invoked only from the Install button gesture. Synthetic events cannot claim eligibility. Prompt acceptance is described as a request, not completed installation. Only the browser `appinstalled` event claims browser-reported installation; unsupported browsers retain an explanatory disabled control and may provide their own menu.

No `skipWaiting`, `clientsClaim`, forced reload, navigation or immediate activation is used, including retirement. An existing waiting worker activates naturally after all old controlled tabs close. “Later” dismisses the notice; unsaved application forms stay untouched. First installation does not seize an existing tab: the next normal navigation may become controlled. Checking updates is explicit and preserves the current view on failure. Install cancellation or unsupported install APIs do not block ordinary online navigation.

## Two-phase removal: required deployment contract

Removing the source or unregistering one browser is not a production retirement. First set `pwaOffline.retired: true`, keep the SAME worker URL, scope and ownership namespace, build and deploy that retirement worker. Stop exposing registration/install UI and the manifest. The retirement worker installs without fetching assets; when old tabs naturally close it removes only its own exact-scope caches and unregisters itself. It never navigates clients or deletes unrelated caches. Retain the retirement script at its original URL for returning clients; offline/dormant devices cannot be certified retired by a server deploy or a finite observation window. Changing filename, base or scope strands old registrations and needs separate retirement of each historical identity.

Only after deploying the retirement artifact and verifying active clients should phase two remove component imports/routes, the native module entry and package dependency, associated reference metadata and tests. Preserve the exact retirement script at `public/pwa-offline-sw.js` (or the original base's deployment path) through all later builds and releases. Retain it as long as old clients may return. Keep reusable authoring source if reinstalling later is desired; do not mistake deletion of authoring source for runtime removal. Unrelated service workers and cache namespaces are never touched.

The generic clean fixture builds and serves native retirement, retains its exact bytes in the original public worker path, then removes the module/dependency and rebuilds a lean consumer. A persistent browser profile proves returning-client cleanup against the final build. This proves only disposable clients; operators must deploy both phases and retain the artifact for all historical scopes. No database data/history exist to remove.
