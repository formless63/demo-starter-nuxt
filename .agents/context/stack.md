# Stack

Exact versions are pinned in `package.json`, capability package manifests, and `bun.lock`; key versions are Nuxt 4.5.2, Vue 3.5.43, TypeScript 5.9.3, Bun 1.4.2, Node 24, Better Auth 1.7.7, `@better-auth/api-key` 1.7.7, Drizzle ORM 0.45.3, pg-boss 12.35.0, `zod-openapi` 6.0.2, `@scalar/nuxt` 0.6.75, PostgreSQL 18, Tailwind CSS 4.3.3, shadcn-nuxt 2.8.2, Reka UI 2.10.5, Tabler Icons 3.48.0, Vitest 5.0.1, and Playwright 1.63.0.

Nuxt/Nitro provides routing, SSR, server routes, runtime configuration, and portable Node output. Better Auth provides database sessions and OAuth; its Nuxt session integration receives `useFetch` for cookie-forwarding SSR. Drizzle/postgres provide typed SQL. `shadcn-nuxt` discovers the restrained components configured by `components.json`; Tailwind provides styling, Reka UI provides primitives, vue-sonner supplies toasts, and color-mode supplies SSR-safe theming. Icons remain Tabler-only. The runtime image uses supported Nitro Node output rather than Bun-specific APIs.

`@repo/nuxt-jobs` is a normal private Nuxt workspace package built with `@nuxt/module-builder`; it provides server-only typed pg-boss integration and a package-owned CLI. pg-boss and registry loading are package dependencies; Nuxt, Drizzle, and Zod are compatible peers. The root reference app and `fixtures/jobs-consumer` both enable it explicitly, while each application owns its task registry. The capability catalog drives generic package preparation, artifact lifecycle testing, and the CI matrix; the fixture retains Jobs-specific runtime checks. Runtime instances disable migration, and the explicit migrator uses pg-boss's supported schema lifecycle. PostgreSQL remains the only infrastructure dependency.

`@repo/nuxt-api` is a sibling private Nuxt workspace package using the same build and catalog-driven lifecycle. It wraps the official Better Auth API-key plugin with hashed, `X-API-Key`-only, user-owned keys that cannot establish browser sessions. The application deliberately composes that helper into its single Better Auth instance and exports the package table from its Drizzle schema. Native Nitro routes use package-provided machine-principal and Zod contract helpers; `zod-openapi` produces the explicit OpenAPI 3.1.1 application surface, and Scalar renders it. Nitro's experimental OpenAPI internals and Better Auth's auth-route OpenAPI are not used as the stable application contract.

`@repo/nuxt-observability` owns Pino 10.3.1, OTel API 1.9.1, stable SDK/core/context/resources 2.11.0 and compatible HTTP/JSON exporters 0.222.0. It uses explicit trace/metric SDKs rather than `sdk-node`, automatic instrumentation or OTel Logs. Nuxt/H3 are peers. Server-only JSON logs, request correlation and safe error/build metadata work without a backend; optional exporters start only with configured endpoints. The fixture proves wire export and bounded shutdown. No extra Compose service or database schema is needed.

`@repo/*` is an internal workspace scope for private packages. It must be replaced by a deliberately selected npm scope before publication. All completed capabilities are optional for clean consumers even though the root reference app enables them for continuous integration.

Docker Compose is the provider-neutral release reference: PostgreSQL 18, an explicit one-shot application plus pg-boss migration service, and the production application and worker. The Docker build bundles minimal Node-compatible migration and jobs entrypoints alongside Nitro so migration and runtime share one immutable image without shipping a second dependency graph. No proxy, orchestrator, cloud manifest, dashboard, or development bind mount is part of the deployment path.

Official Nuxt documentation should be the primary source. Agents supporting MCP can connect to Nuxt's credential-free official endpoint `https://mcp.nuxt.com/mcp`; it is intentionally documented rather than committed as personal editor configuration. MCP is development-only and has no runtime role.

`@repo/nuxt-storage` owns AWS SDK v3 S3 client/presigner 3.1143.0 with Nuxt as peer, no database/auth/other capability dependency. Server-only configuration is lazy and preserves default AWS credential discovery without static credentials. Region resolves STORAGE_REGION → AWS_REGION → AWS_DEFAULT_REGION → error on use; no implicit region. Private objects, stream lifecycle, exact signed PUT headers, multipart and post-upload HEAD policy are its contract; UI/records/processing are not. Optional app-owned telemetry uses bounded `app.storage.*` instruments. Actual fixture parity uses RustFS 1.0.0 and Garage 2.4.1; optional third-party Noooste Garage UI v0.13.0 is localhost/operator-only, not official or required for S3, with privileged admin-token access isolated from application browser code/S3 clients. `compose.storage.yaml` shares fixture-owned local definitions and is not required by normal production Compose. See `OBJECT_STORAGE_MODULE_EVALUATION.md` for shared defaults and signing/checksum/CORS/portability limits.

`@repo/nuxt-email` owns Nodemailer 10.0.13 with Nuxt as peer. Explicit SMTP security, bounded structured messages and safe single-attempt error/result handling are server-only; Mailpit1.31.3 is optional disposable test/dev infrastructure. Root Better Auth and telemetry composition introduce no package dependency.

`@repo/nuxt-webhooks` has a hard Jobs peer/module/catalog dependency; Nuxt/Zod are peers. Node 24 native fetch/crypto implement Standard Webhooks HMAC exact-byte signing. `standardwebhooks` 1.1.1 is a root test-only interoperability oracle; optional Audit/API/Observability remain dependency-free.

`@repo/nuxt-audit-log` uses Nuxt/Drizzle peers and @nuxt/kit only; no API/Jobs/auth dependency. Application-generated UUIDs, timestamptz(3), bounded JSONB metadata and four B-tree indexes support append-oriented records and exact keyset queries.

`@repo/nuxt-cache` owns stable redis/node-redis 6.3.0 with Nuxt peer and official Valkey 9.1.2 disposable fixture. Node 24 production and Bun tooling share the verified protocol subset; TLS verification stays enabled. Additive `compose.cache.yaml` is loopback-only with no AOF/RDB/data volume. Cache is ephemeral; Jobs remains PostgreSQL-durable. See `CACHE_COORDINATION_MODULE_EVALUATION.md`.

`@repo/nuxt-realtime` uses H3/Zod peers and current Nitro2.13.4/CrossWS0.3.5 mechanisms; no Socket.IO or new transport dependency. Node PassThrough/H3 sendStream provides SSE comments/drain; native H3 WebSocket hooks provide authenticated Upgrade and send-buffer signals. Nitro's experimental websocket flag is necessary; Node24 global WebSocket is a stable client API. Runtime default SSE; both adapters always available.

`@repo/nuxt-notifications` uses Jobs/Drizzle/Zod peers and native Node24 fetch for optional ntfy JSON. Schema has its own entry for Drizzle Kit compatibility. Actual fixture uses pinned stable ntfy2.28.0 (disposable local server); root Email adapter reuses Nodemailer10.0.13/Mailpit1.31.3 rather than adding SMTP. No optional capability dependency or new mandatory service.

@repo/nuxt-search uses normal Nuxt module-builder and compatible Nuxt/Drizzle peers; existing PostgreSQL 18 FTS only. simple weighted vectors, parameterized websearch_to_tsquery and ts_rank_cd normalization 32; no external search service or pg_trgm.

`@repo/nuxt-ai` owns OpenAI SDK 7.25.0 and Zod 4.6.5 with Nuxt peer/module-builder. Chat Completions SSE supports configured compatible endpoints on Node 24/Nitro; retries/logging are explicitly disabled. Default provider openai-compatible, timeout 60 seconds, optional key, lazy required model; see AI_MODULE_EVALUATION.md for the prompt-derived v1 contract.

`@repo/nuxt-medusa` uses bounded native fetch against pinned Medusa2.21.2, Basic Admin auth, Jobs/Webhooks/Drizzle/Zod peers and the existing Webhooks signer/verifier. No SDK/backend dependency graph in starter runtime. The separate pinned backend fixture installs its own graph in a disposable directory; workflow product events differ from internal module events.

`@repo/nuxt-invoice-ninja` uses native fetch with Jobs/Webhooks peers against pinned Invoice Ninja 5.13.43 (`382020072bc79e8c7ede49f7e9ce91b0aeb1a051`); the disposable official-image/MariaDB fixture passed numeric-string draft/GET and isolated unsent zero-tax/discount proof. Reference draft policy remains absent pending deployment-specific evidence. `@repo/nuxt-stripe` owns stripe-node 23.0.0/API 2026-09-30.endive with operation-local FetchHttpClient, retries/telemetry disabled and native raw signature verification. Its verified local wire/database fixtures do not contact Stripe or certify financial activity. All three provider capabilities are `done`, with full combined CI and generic packed install/runtime/removal coverage; Medusa’s separate pinned backend/subscriber fixture also passed.
