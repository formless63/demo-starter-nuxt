# Stack

Exact versions are pinned in `package.json`, capability package manifests, and `bun.lock`; key versions are Nuxt 4.5.2, Vue 3.5.43, TypeScript 5.9.3, Bun 1.4.2, Node 24, Better Auth 1.7.6, `@better-auth/api-key` 1.7.6, Drizzle ORM 0.45.3, pg-boss 12.35.0, `zod-openapi` 6.0.2, `@scalar/nuxt` 0.6.75, PostgreSQL 18, Tailwind CSS 4.3.3, shadcn-nuxt 2.8.2, Reka UI 2.10.5, Tabler Icons 3.48.0, Vitest 5.0.1, and Playwright 1.63.0.

Nuxt/Nitro provides routing, SSR, server routes, runtime configuration, and portable Node output. Better Auth provides database sessions and OAuth; its Nuxt session integration receives `useFetch` for cookie-forwarding SSR. Drizzle/postgres provide typed SQL. `shadcn-nuxt` discovers the restrained components configured by `components.json`; Tailwind provides styling, Reka UI provides primitives, vue-sonner supplies toasts, and color-mode supplies SSR-safe theming. Icons remain Tabler-only. The runtime image uses supported Nitro Node output rather than Bun-specific APIs.

`@wicaso/nuxt-jobs` is a normal Nuxt workspace package built with `@nuxt/module-builder`; it provides server-only typed pg-boss integration and a package-owned CLI. pg-boss and registry loading are package dependencies; Nuxt, Drizzle, and Zod are compatible peers. The root reference app and `fixtures/jobs-consumer` both enable it explicitly, while each application owns its task registry. The capability catalog drives generic package preparation, artifact lifecycle testing, and the CI matrix; the fixture retains Jobs-specific runtime checks. Runtime instances disable migration, and the explicit migrator uses pg-boss's supported schema lifecycle. PostgreSQL remains the only infrastructure dependency.

`@wicaso/nuxt-api` is a sibling Nuxt workspace package using the same build and catalog-driven lifecycle. It wraps the official Better Auth API-key plugin with hashed, header-only, user-owned keys that cannot establish browser sessions. The application deliberately composes that helper into its single Better Auth instance and exports the package table from its Drizzle schema. Native Nitro routes use package-provided machine-principal and Zod contract helpers; `zod-openapi` produces the explicit OpenAPI 3.1.1 application surface, and Scalar renders it. Nitro's experimental OpenAPI internals and Better Auth's auth-route OpenAPI are not used as the stable application contract.

Docker Compose is the provider-neutral release reference: PostgreSQL 18, an explicit one-shot application plus pg-boss migration service, and the production application and worker. The Docker build bundles minimal Node-compatible migration and jobs entrypoints alongside Nitro so migration and runtime share one immutable image without shipping a second dependency graph. No proxy, orchestrator, cloud manifest, dashboard, or development bind mount is part of the deployment path.

Official Nuxt documentation should be the primary source. Agents supporting MCP can connect to Nuxt's credential-free official endpoint `https://mcp.nuxt.com/mcp`; it is intentionally documented rather than committed as personal editor configuration. MCP is development-only and has no runtime role.
